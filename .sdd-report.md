## Summary

Implemented categorized root `--help` for `onebrain`. The flat Commands list is replaced by four named sections; subcommand help is untouched.

---

## Design

### Mechanism

clap v4's derive macro has no native category headings. The implementation intercepts the root help path in `main` before `Cli::try_parse()`:

1. `is_root_help_request(&raw_args)` detects `onebrain --help`, `-h`, or bare `onebrain`. Returns false for `--version`, subcommand help, or any non-root invocation.
2. `print_root_help()` builds the categorized block from live `Cli::command()` subcommand `about` strings, then:
   - Clones the root `Command` and injects the block via `.before_help()`
   - Hides all subcommands on the clone so clap's `{all-args}` token renders only the Options section
   - Calls `print_help()` (not `print_long_help()`) to preserve compact Options format — `print_long_help()` forces `use_long = true` which puts every option on its own line; `print_help()` keeps the original compact row layout
   - Exits 0

### Category structure

```
Setup & Maintenance   init, update, doctor, plugin, qmd
Vault & Content       vault, note, task
Session & Automation  session, checkpoint, schedule, skill
AI & Serving          harness, serve
```

### Drift guard

`drift_guard_category_map_complete` in `categorized_help.rs` (unit test, no binary needed):
- Every visible root subcommand must be in exactly one category
- Every category entry must correspond to a visible subcommand
- No duplicates

CI fails immediately if a new visible command is added without categorising it, or a stale entry is left after hiding a command.

## Key Decisions

**Why `print_help()` not `print_long_help()`:**
`print_long_help()` passes `use_long = true` directly to the HelpTemplate renderer, which forces every option onto its own line (next-line format). clap's internal `--help` handler calls `write_help_err` which coerces `use_long = use_long && long_help_exists()` — since no args have `long_help` annotations, `use_long` becomes false and the output is compact. Using `print_help()` makes this same coercion explicit without relying on the internal path.

**Why hide subcommands instead of custom template:**
A custom `help_template` with `{options}` also renders in long format (same `use_long` issue). Hiding all subcommands on a render clone makes clap's default template render only the Options block, with no Commands section — our `{before-help}` block fills the command-listing role instead.

**`--version` intercept bug caught by `real_binary_version_output_passes_update_validator`:**
The initial `is_root_help_request` had a catch-all `.all()` clause that treated `--version` as a root help request. Fixed to require `has_help_flag || after_bin.is_empty()` only — `--version` now passes through to clap's normal parse path.
